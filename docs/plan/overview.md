# Reproduction Plan Overview

- 阶段0：项目立项
- 阶段1：先做 baseline，不急着上完整光学系统
- 阶段2：验证数据链路和评估链路
- 阶段3：实现光学模块，但先做“模块验证”，不要直接全系统训练
- 阶段4：做最小闭环训练
- 阶段5：对齐论文设定
- 阶段6：系统化实验与消融
- 阶段7：整理复现结论

## 阶段0：项目立项

目标不是写代码，而是把任务定义清楚。

你要完成：

1. 建 GitHub 仓库
2. 写 README 初版
3. 写 `paper_notes.md`
4. 写 `reproduction_plan.md`
5. 搭好目录结构
6. 建最小环境文件 `requirements.txt` 或 `environment.yml`

这一阶段的产物是：

- 项目有骨架
- 论文目标明确
- 你知道要复现什么，不复现什么

------

## 阶段1：先做 baseline，不急着上完整光学系统

这是很多人会犯错的地方。

不要一开始就把所有复杂模块全接上。
 你应该先建立“下界”和“上界”。

至少做两个 baseline：

## baseline A：简单插值

- bicubic / bilinear

作用：

- 确认评价流程正常
- 给出最基础参考线

## baseline B：纯电子网络

- 一个简单 CNN / UNet / SRCNN 风格网络

作用：

- 确认数据与训练流程能工作
- 判断任务本身是否合理
- 给出“电子上界参考”

这一步特别重要。

如果你上来就做光电混合网络，结果差，你根本不知道：

- 是任务难
- 是数据问题
- 是评估错
- 还是光学层的问题

但如果纯电子 baseline 正常，而混合网络不行，那问题范围立刻缩小。

------

## 阶段2：验证数据链路和评估链路

你要单独确认：

1. 数据集是否正确下载/整理
2. LR-HR 对是否对应
3. 放大倍率是否一致
4. patch 裁剪是否正确
5. PSNR / SSIM 是否与论文口径一致
6. 保存的可视化是否真实反映结果

这个阶段建议你做一件很工程、很值的事：

> 随机抽几对数据，直接保存成图片，看 LR、HR、重建结果是否肉眼合理。

很多 bug 是肉眼一看就知道有问题。

------

## 阶段3：实现光学模块，但先做“模块验证”，不要直接全系统训练

比如你要做衍射传播层，你先检查：

- shape 对不对
- 数值是否稳定
- 前向是不是符合预期
- 参数是否可训练
- 梯度能否正常回传

甚至可以先不接完整超分头，只看：

- 某个输入通过光学模块后输出是否合理
- 多层传播后能量是否严重偏移
- 相位图是否更新正常

这一步的核心是：

> **先验证模块存在“物理/数值合理性”，再验证任务性能。**

------

## 阶段4：做最小闭环训练

这一步不是追论文指标，而是确认整个系统“能学”。

你应该做：

1. 小数据集训练
2. 小 batch
3. 短 epoch
4. 保存中间输出
5. 看 loss 是否下降
6. 看 1 张图是否能过拟合

这个阶段最重要的问题只有一个：

> **整个系统有没有梯度驱动下的可学习性？**

如果这里都不通，就不要急着调大实验。

------

## 阶段5：对齐论文设定

现在才开始认真对齐论文。

包括：

- 数据集版本
- 图像尺寸
- 放大倍率
- 优化器
- 学习率
- 损失函数
- 初始化
- 正则项
- 训练轮数
- 评估方式

这里你要非常警惕一个事实：

> 论文正文通常不会写全所有关键细节。

所以你要建立一个“未确定项清单”：

- padding 未说明
- 边界裁剪未说明
- 相位初始化未说明
- 传播模型实现细节未说明
- 归一化方式未说明

然后逐项验证，不要假装它们不存在。

------

## 阶段6：系统化实验与消融

当你有一个“能跑”的版本后，就进入真正的工程复现阶段。

你要做的不是乱试，而是**成体系地试**。

例如：

- 是否加正则项
- 不同传播距离
- 不同衍射层数
- 不同 loss 组合
- 不同上采样方式
- 不同 patch size
- 不同初始化

这时配置管理、实验日志、Git commit、issue 就全部开始发挥价值。

因为你需要回答的不是：
 “哪个好像更好？”

而是：
 “哪一个因素真正影响结果？证据是什么？”

------

## 阶段7：整理复现结论

最后不是“代码能跑就结束”，而是要形成结论：

1. 哪些部分成功复现
2. 哪些部分没复现出来
3. 差距可能来自哪里
4. 哪些工程细节最关键
5. 哪些地方论文写得不清楚
6. 哪些模块值得进一步改进

这一步会直接决定你这个项目有没有“研究价值”。

因为真正好的复现，不只是“我也跑到了 28.5 dB”，而是：

- 我知道为什么能到
- 我知道为什么到不了
- 我知道哪些细节决定成败
