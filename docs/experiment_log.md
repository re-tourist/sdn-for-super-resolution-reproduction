# Experiment Log

本文件用于记录复现过程中的实验、排查、阶段推进与重要工程动作。  
记录目标不是“堆很多字”，而是保证每次关键修改都可追踪、可回溯、可总结。

---

## 日志字段说明

- **实验编号**：建议用 `Exp-000`、`Exp-001` 这种格式
- **阶段**：对应当前所处阶段（0~6）
- **目标**：这次工作/实验是为了解决什么问题
- **配置**：使用的配置文件或关键参数
- **代码版本**：建议填写 commit hash 或分支名
- **修改内容**：相较于上一次改了什么
- **结果**：客观现象与指标
- **观察**：你从结果中看到了什么
- **结论**：这次工作说明了什么
- **下一步**：接下来最合理的动作

# 推荐记录规则

## 1. 什么情况应该记一条日志？
以下情况建议至少记录一条：

- 完成一个阶段性工程动作
- 跑了一个正式 baseline
- 修改了关键配置
- 修复了一个重要 bug
- 发现论文中的一个关键未明确项
- 得到了一次值得保留的实验结果
- 结论发生变化

## 2. 不要只记“做了什么”，还要记“为什么”
例如不要只写：
- 改了学习率

更好的是写：
- 将学习率从 1e-4 改为 5e-5，目的是缓解训练初期不稳定

## 3. 结论要尽量可操作
例如：
- 当前结果说明纯电子 baseline 可以学习，问题更可能集中在光学模块

这样的结论比“效果一般”有用得多。

## 4. 第0阶段也要记
例如：
- 仓库初始化完成
- 配置系统骨架完成
- 论文未明确项整理完成

这些记录对后续写报告和回顾非常有价值。
